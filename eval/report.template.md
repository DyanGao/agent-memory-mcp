# Evaluation report

Generated by `eval/report.py` from `eval/results`, newest copy of each result, {{date}}. This covers the parts of [EVAL_PLAN.md](../EVAL_PLAN.md) that run on local models. Models: `qwen3` for distillation, `bge-m3` for embeddings, on one Mac.

**Not measured yet:** answer accuracy, tokens per query, comparison with the baselines, and coding-agent task success. These need the paid judge and agent runs, so the README results table is still empty. Every run here is a single run, not the 3 runs with mean ± std that the plan calls for.

## Deletion

50 planted personal facts, each with its own user and 9 unrelated keeper memories. After the forget, 200 probes in four styles (direct, reworded, indirect, prompt injection) ran through `memory_search` and `memory_context_for`, along with `memory_list`, the data export and a scan of every table. A probe leaks if a word unique to the fact comes back.

{{deletion}}

- **Reworded topics fail without review.** A topic sharing no words with the fact deletes nothing. No single similarity cutoff fixes this: 0.5 finds all 50 facts but wrongly matches other topics in 30 cases, and deletion cannot be undone. Automatic deletion stays strict, and the preview lists possible matches to tick.
- **The review result has a limit.** {{offered}} facts were offered, with {{candidates}} candidates per preview on average, but the eval stands in for the person and always ticks correctly. It shows the fact is offered and that deleting it works, not that people choose correctly.
- **The distiller kept only {{kept}} of these facts**, as it treats personal facts as off-topic for coding. Each fact was also stored with `memory_write`, so that every fact existed to be forgotten.

## Scale

Synthetic vectors, one client, excluding embedding and LLM calls, at the default `ef_search` of 400.

{{scale}}

- **Latency meets the target:** the plan asks for under 150 ms at 10k.
- **Recall is unresolved at 100k.** Clustered vectors stay near 1.0, while uniform random vectors, HNSW's hard case, fall to about 0.26. Real embeddings sit somewhere between, and synthetic clusters may be easier than real data. Only a real corpus can settle this, and it should be measured before any claim is made about retrieval at this size.
- **Rows at `ef_search` 200 in the raw results are not index recall.** Their recall of 1.0 at about 130 ms shows the planner chose an exact scan.
- **Search also uses full-text ranking,** so vector recall alone does not decide retrieval quality. How much that helps has not been measured.

## Coding-agent pilot

5 tasks, 1 run each, on Claude Code with Haiku. Session 1 makes a decision in conversation only, and session 2 needs it, in a separate folder. Hidden tests decide the result.

{{pilot}}

- **This shows the pipeline carries a decision end to end.** It does not show a general benefit: see the harder pilot. Each task needs a fact that exists nowhere else, so no-memory failing is close to guaranteed by the design.
- **Full history tied because that history is tiny.** One short exchange costs almost nothing to replay. Memory only earns its place with long histories, which this pilot does not test.
- **Runs used the machine's global Claude Code instructions.** They applied equally to all setups, but they must be removed for a run others can reproduce.

## Harder coding pilot

The same 5 tasks, on one long history of 8 sessions (about 49,000 characters): three decisions that later change, two rules spread across sessions, near-miss distractors, and ordinary chatter. Personal Claude Code settings were excluded.

{{hard}}

**Before the fixes, memory lost badly, because the system was damaging its own data.** Tracing each lost decision found four causes:

- **Consolidation destroyed true facts.** "All prices are in euros" was superseded by "The repo is not a git repository". An exception replaced the rule it added to, and a prefix change wiped the rest of an id format. This came from an earlier fix for a stale-fact bug.
- **Extraction missed decisions** buried in chatter.
- **Retrieval favoured noise.** A vague session-start query put "not a git repository" first and left out the 30% discount cap.
- **Session status was stored as memories.**

**What the "after" figure does and does not show:**

- These are the tasks and history the fixes were tuned on, so 4 of 5 is not an unbiased score. It is one run of each.
- Full history still passes more. The remaining failure is the dispute rule, which was never extracted.
- This history is about 49,000 characters. Memory cost about 30% less than full history per task, but a history this size is too short to show the token saving the project is meant to deliver.

### Held-out store check

A second history, written after the fixes and scored once, with no tuning. It covers store quality only, with no agent runs.

- **{{held}} current decisions were stored,** close to the 13 of 14 on the tuned history, so the fixes generalise to a real degree.
- **One invented memory.** "Exports exclude reports from before 2020" appears nowhere in the history. It was copied from an example in the distiller prompt. This is not fixed yet, and it is the most serious finding here: a memory system must not state things nobody said.
- **Decisions the agent proposes are lost.** When the agent suggested Argon2id and the user replied "yes, go with that", nothing was stored, because extraction now reads mostly what the user says.
- **One stale value survived.** A change of backup time from 02:00 to 04:00 was not extracted, so the old time stays current.

## What this eval changed in the product

- Reworded topics now need human review, because automatic matching could not be made safe.
- Forgetting a memory also removes transcripts repeating its words.
- The distiller no longer cuts a memory off at a double quote. The pilot found this on its first task: a rate limit arrived with its response body missing. The fix is a prompt rule, so another model could still do it.
- Consolidation now replaces only a specific changed value, and writes merged text that keeps everything else. Extraction reads what people said, in small pieces. Session status is filtered in code. A new session gets decisions first instead of a vague search.
- `ef_search` went from 100 to 400, nearly doubling worst-case recall at 10k for under 3 ms.
- Postgres now gets 1 GB of shared memory. Docker's default of 64 MB is too small for parallel vector index builds, including the one in the nightly scrub.
- The scrub now holds its lock for 19.6 s at 100k clustered, down from 82 s, and retries after a failure.

## Known weaknesses

- **Vector ranking on real data.** One real query ranked the right memory last of 4 by meaning, and the importance score rescued it.
- **No minimum relevance.** Small stores return unrelated memories.
- **Memory poisoning.** Skipping tool output closes the main route, but text the user pastes, or that the agent repeats, can still be stored. No poisoning case is scored yet.
- **Importance scores** are narrow, mostly 0.5 and 0.7.
- **Session noise is reduced, not gone.** The pilot's 46 memories held 5 real decisions. A long history now gives 15 memories, 1 of them noise, but the held-out history still kept lines like "Standup is at ten tomorrow".

## Reproduce

```bash
make eval-up
make eval-full
cd eval && uv run python report.py
```

`make eval-quick` needs no models. It replays recorded `bge-m3` vectors through the real forget code, and runs in CI.
